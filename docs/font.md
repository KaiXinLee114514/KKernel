# Chinese Text and Fonts

> Originally README §9; for how the data is generated, see font/README.md.

Chinese **displays correctly**: in graphics mode the 16×16 bitmap is blitted straight into the framebuffer, so `cat DOCS/ZH.TXT` shows it (the demo texts ship in the image; one .TXT each for Chinese/Japanese/Korean/English, not exposed as commands).

Data source and generation are described in [font/README.md](../font/README.md): the `font/` directory holds glyphs extracted from GNU Unifont (what's checked in is a 23 KB `.hex` subset of 416 glyphs plus the binary; the full 42,112-glyph, 1.8 MB font **lives in the disk image**, generated by `tools/mkfontsubset.py`). **It is licensed separately under GPL-2+** (not merged into the repo's MIT).

**Encoding status**: character numbers are standard Unicode code points, and **kernel text is standard UTF-8 too** — `term_print` decodes UTF-8 into code points before drawing (see `kernel/utf8.asm`), so Chinese strings can be written into the kernel like any other string, `db '你好,世界!', 0`, and the same goes for programs; bad bytes draw as the replacement character `�` instead of hanging. Details (including the history of the old "code point array" scheme) are in [docs/encoding.md](encoding.md).
