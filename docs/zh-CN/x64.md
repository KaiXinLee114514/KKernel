# x86-64 start64（Phase 1 MVP）

> 32 位内核现在可以把控制权交给一个**真正的 64 位内核**：在 shell 里敲 `start64`，
> 内核从 FAT 磁盘读出 `BIN/K64.BIN`，建好页表、置上 `EFER.LME`，跳进长模式；
> 随后独立的 64 位内核带着自己的 GDT / IDT / PIC / PIT / 键盘驱动 / LFB 控制台 / shell 接管。
>
> 这是**单向**的：Phase 1 不做 `start32`，除了 `reboot` 没有回头路。
> 这一阶段的目标是跑通一条干净、自包含的 64 位启动链路，并用 shell 证明长模式、
> 中断、键盘和帧缓冲都工作正常。

## 已经能干什么

- 32 位侧：`start64` 命令（`kernel/x64.asm`）
  - CPUID 检查：PAE（leaf 1，EDX bit 6）+ 长模式（leaf `0x80000001`，EDX bit 29）；
    不支持的 CPU 会打印友好错误而不是崩溃；
  - 走正常 FAT 驱动把 `BIN/K64.BIN` 读到物理地址 `0x200000`（上限 128 KiB）；
  - 在 `0x1FF000` 填一个 `K64I` boot-info 结构；
  - 建恒等页表（2 MiB 大页）：`0x00000000-0x3FFFFFFF`，外加 VBE LFB 窗口
    `0xC0000000-0xFFFFFFFF`；
  - 切长模式并远跳到 `0x200000`。
- 64 位侧（`kernel64/`，链接在 `0x200000` 的平铺二进制，`nasm -f bin` 汇编）：
  - 自己的 GDT 和 256 项 IDT；32 个异常 stub 会打印向量 / 错误码 / RIP / CS 后停机，
    而不是三连故障；
  - PIC 重映射到 `0x20`/`0x28`，PIT 100 Hz，PS/2 键盘 set-1 扫描码翻译
    （字母、数字、shift、空格、回车、退格）；
  - 直接写 VBE 32bpp LFB 的控制台（默认 800×600），用与 32 位控制台相同的 8×16 ASCII
    字模，支持滚动、绿/白配色；
  - shell 命令：`help`、`info`、`echo`、`clear`、`ticks`、`reboot`；
  - `info` 打印 CPU 厂商、CR0/CR4/EFER、`PAE=1 LME=1`、内存、LFB 和 K64 镜像位置。
- 测试：`make -s test-k64` 在 32 位 shell 登录后执行 `start64`，断言横幅、`k64>`、
  `info`（`PAE=1`、`LME=1`）、`echo hello64`、`ticks`，最后 `reboot`
  （因为有 `-no-reboot`，QEMU 会直接退出）。

## 用法

在 32 位 shell 里（硬盘镜像，登录 `root`/`root`）：

```text
(・ω・)> start64
start64: jumping to 64-bit kernel at 0x00200000 (long mode)
KKernel x86-64
long mode: enabled
  LFB: 0xFD000000 800x600x32
  RAM: 127 MiB, E820 entries: 7
  K64: 0x00200000, 11040 bytes
k64> info
...
k64> reboot
```

> ⚠️ **QEMU 注意**：`qemu-system-i386` 不能模拟长模式——它所有 CPU 模型的 CPUID
> 长模式位都被过滤掉了，所以 `start64` 会正确地报 "CPU does not support long mode
> (PAE/LM)"。`--k64` 测试和手工运行必须用 `qemu-system-x86_64`（配 `-cpu qemu64`
> 或更好）。这是 i386 模拟器目标本身的限制，不是内核的 bug。

## 启动信息块（`0x1FF000`）

| 偏移 | 大小 | 含义 |
|---|---|---|
| 0 | 4 | magic `K64I`（`0x4934364B`） |
| 4 | 4 | LFB 物理地址 |
| 8 | 4 | LFB pitch（每行字节数） |
| 12 | 4 | LFB 宽度（像素） |
| 16 | 4 | LFB 高度（像素） |
| 20 | 4 | LFB 每像素位数 |
| 24 | 4 | E820 条目数组指针（`0x9400`） |
| 28 | 4 | E820 条目数 |
| 32 | 4 | 内存顶端（MiB） |
| 36 | 4 | K64 镜像物理地址（`0x200000`） |
| 40 | 4 | K64 镜像大小（字节） |
| 48 | 8 | 64 位栈顶（`0x1EF000`） |

## 32 位 → 64 位内存布局

| 物理地址 | 用途 |
|---|---|
| `0x00100000+` | 32 位内核、FAT 缓冲、程序窗口、pmem 页池（不变） |
| `0x001E0000` | PML4（一项） |
| `0x001E1000` | PDPT（0–1 GiB 恒等 + 3–4 GiB LFB 窗口） |
| `0x001E2000` | PD0：512 个 2 MiB 大页覆盖 `0x00000000-0x3FFFFFFF` |
| `0x001E3000` | PD3：512 个 2 MiB 大页覆盖 `0xC0000000-0xFFFFFFFF`（LFB 在 `0xFD000000`） |
| `0x001EF000` | 64 位内核栈顶 |
| `0x001FF000` | boot info（`K64I`） |
| `0x00200000` | `BIN/K64.BIN` 装载地址 / 64 位内核 `ORG` |

页表区（`0x1E4000` 之前的 1.5 MiB）和 boot-info 页 32 位内核都没用，可以安全挪用。
`retf` 触发 `#GP` 的教训：当 `EFER.LMA=1`（还在兼容模式）时，QEMU 会把 `LGDT`
的操作数按完整的 10 字节描述符读取；而且在真正执行 64 位代码之前，数据段描述符不能带
`L=1` —— 所以切换用的 GDT 里数据段用普通 32 位兼容描述符，等远跳之后再让 64 位内核
重新加载自己的 GDT。

## 构建、运行、测试

```bash
make k64                                   # 生成 build/K64.BIN（64 位平铺二进制）
make -s -B build/kkernel-hd.img            # 把 BIN/K64.BIN 打进 FAT 镜像
make -s test-k64                           # 自动化 QEMU 测试（x86_64 模拟器）
# 手工：
qemu-system-x86_64 -m 128 -cpu qemu64 -boot c \
  -drive file=build/kkernel-hd.img,format=raw,if=ide,index=0 \
  -display none -no-reboot -monitor unix:/tmp/kk.mon,server,nowait
```

尺寸（Phase 1）：32 位 `kernel.bin` 约 155 KiB（上限 256 KiB）；`K64.BIN` 约 11 KiB
（上限 128 KiB，必须能一次 FAT 读完）。

## 文件

| 文件 | 作用 |
|---|---|
| `kernel/x64.asm` | 32 位侧：`start64` 命令、CPUID 检查、页表、长模式切换 |
| `kernel64/start.asm` | 64 位入口、自己的 GDT、boot-info 校验、初始化序列 |
| `kernel64/console.asm` | 直接写 LFB 的 32bpp 文本控制台（8×16 ASCII 字模、滚动） |
| `kernel64/idt.asm` | 64 位 IDT、异常 stub、PIC 重映射、PIT 与键盘 IRQ 处理 |
| `kernel64/shell.asm` | 64 位 shell：`help / info / echo / clear / ticks / reboot` |
| `tools/mkfont8x16.py` | 从 `font/font-kkf.bin` 提取 ASCII 8×16 字模 |
| `build/font8x16.bin` | 生成的字模数据，被 `kernel64/start.asm` 用 `incbin` 引用 |
| `tests/qemu_test.py --k64` | 自动化测试（用 `/usr/bin/qemu-system-x86_64`） |

## 已知限制（Phase 1）

- 单向：没有 `start32`，回不到 32 位内核；`reboot` 是重启整台机器。
- 64 位内核是一个单线程 ring 0 程序：没有用户态、没有进程、没有调度器、没有页分配器、没有 swap。
- 只驱动它需要的硬件：PIC（8259A）、PIT（通道 0，100 Hz）、PS/2 键盘控制器、
  VBE 线性帧缓冲。没有磁盘驱动、USB、网络、输入法。
- 键盘只支持 US QWERTY（set-1 扫描码）；除基本 shift 外没有小键盘/方向键/扩展键。
- 32 位内核必须保持在 256 KiB 以内，`K64.BIN` 必须在 128 KiB 以内（单次 FAT 读上限）。
